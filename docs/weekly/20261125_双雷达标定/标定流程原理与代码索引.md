# 本次双雷达标定：流程、原理与代码

本文解释2026-11-25实际运行的实现。核心是静止点云的刚体几何配准，没有训练神经网络，也没有在线修改雷达固件。现阶段分为原点到平面ICP流程、共同大平面实验分支及车体外参核对；共同平面分支还没有整合成任意场景自动标定入口。

## 1. 求解什么

令F为前左雷达光学坐标系、R为后右雷达光学坐标系。寻找旋转矩阵R_RF和位移t_RF，使同一物体满足：

```text
p_R = R_RF · p_F + t_RF
T_R_from_F = [ R_RF  t_RF ]
             [  0      1 ]
```

旋转有3个自由度，平移有3个自由度，共6个。代码以4×4矩阵为权威结果；显示用的rpy遵循SciPy xyz欧拉角约定。需要将点云转换至车体B时：

```text
T_B_from_F = T_B_from_R · T_R_from_F
```

所以，即使两台雷达彼此对齐，也不能由此知道车体原点在哪里或机械车头朝哪边。后右到车体的绝对锚点仍须机械资料、实测或另有参考的运动标定。

内参是雷达内部距离/角度模型，时间同步是数据对应时刻，外参是安装空间关系。本次墙角采集只处理相对外参，不能把点云残差直接当作距离偏置写入厂家内参。

## 2. 从设备到原始数据

```text
MID360S点云与IMU UDP报文
  → Livox SDK2 / livox_ros_driver2（C++）
  → 每台独立的PointCloud2、Imu话题 + 设备诊断/同步状态
  → capture.py（Python/rclpy）
  → 点云NPZ、IMU NPY、metadata.json、diagnostics.json、驱动日志
```

驱动以10Hz发布点云；30秒窗口每台收到约300帧点云、6000帧IMU。采集程序检查所有消息的流统计，点云每5帧保留1帧用于离线几何，按采集时间分为前半段和后半段。当前不是完整原始UDP包或全字段rosbag归档：用于标定的NPZ主要保存XYZ及所抽帧的时间戳。

预热8秒，静止采集30秒。驱动内部外参全部置零，否则可能在驱动中变换一次、离线中再变换一次。预检包括雷达IP/序列号、网口、主钟状态、端口和进程冲突；采集中检查实时设备偏差、诊断新鲜度、点云/IMU频率、时间戳连续性以及正常退出清理。

代码：本地工具`双雷达标定工具/capture.py`的`preflight()`、`run()`；部署包驱动`navigation/driver_workspace/src/livox_ros_driver2/src/lddc.cpp`负责ROS点云/IMU消息组织和发布。

## 3. 数据检查与静止性

- 原始health_ok严格保留。仅历史码04050002且其余检查全部合格时，另给“静止几何资格”；0402/0406、实时超限等不会豁免。
- IMU检查角速度与加速度波动；但匀速平移可能不明显，因此还要把同一台雷达的前后半段点云配准，检查是否移动车体或改变场景。
- 前后半段配准位移超过15mm或转角超过0.3°则拒绝；还检查几何约束是否退化。
- 几何拟合过滤无效值，使用1–10m范围，减轻近车体反射和远处稀疏点影响。

对应`static_policy.py:qualify_static()`及`calibrate.py:capture_data()`。IMU在这套静止几何流程中主要用来检查静止，没有用IMU积分移动轨迹来求双雷达外参。

## 4. 原方案：多尺度点到平面ICP

核心在`registration.py:fit()`。

先用体素网格减少密度差异；每个体素保留一个代表点。对目标点周围20个近邻做协方差分解，最小特征值对应的向量作为局部平面法线，剔除不够平面的邻域。KD-tree用来快速找最近邻。

对前左点p、后右对应点q及其局部法线n，残差为：

```text
x = R · p + t
r = nᵀ · (x − q)
```

这表示点偏离目标平面的垂直距离。以微小旋转δθ和平移δt线性化后，雅可比为：

```text
J = [ (x × n)ᵀ   nᵀ ]
J · [δθ, δt]ᵀ ≈ −r
```

实际核心代码：

```python
x = moved[keep]
n = normal[keep]
res = np.sum((x - target_points) * n, axis=1)
a = np.column_stack((np.cross(x, n), n))
weights = 1 / np.sqrt(1 + (res / .035) ** 2)
delta = np.linalg.lstsq(a * weights[:, None], -res * weights, rcond=None)[0]
```

权重降低大残差点的影响，不能保证全部错误对应都被去掉。按12cm→7cm→4cm体素逐级细化，每级最多35次迭代，并限制单步更新幅度。将更新左乘到当前变换，逐步缩小残差。

`calibrate.py:solve()`对每个训练位置使用初始偏航0°、−2°、+2°分别求解。只按训练组表现选候选，再检查不同训练位置/初值的解是否一致。最近邻配准依赖合理初值，不能保证任意安装方向都找到全局正确解。

原方案第一轮训练解平移跨度21.51mm，第二轮11.19mm，均超过10mm门限，因此原正式报告保持REJECTED，不能因为某张验证图好看就改成通过。

## 5. 本次新候选：共同大平面等权求解

`标定稳定性复核_20261125/audit_planes.py`提取主要平面：利用局部法线随机采样寻找支持点多的平面，再用PCA细化；依据初步对齐后的法线方向和距离匹配两台的平面。

`fit_common_planes_candidate.py`选择双方至少5000个平面支持点、两个切向标准差均大于0.35m的大平面。本次各组选到两面墙和顶部平面，不是强制墙角90°，也不能把顶部称为地面。自动对应还要目视检查。

对已同向的单位平面法线及平面方程：

```text
n_Fᵀ p_F = d_F
n_Rᵀ p_R = d_R
```

理想刚体变换满足：

```text
n_R = R_RF · n_F
n_Rᵀ t_RF = d_R − d_F
```

先让多组法线方向尽量对齐，再用平面距离解平移：

```python
rotation, _ = Rotation.align_vectors(target_normals, source_normals)
translation = np.linalg.lstsq(
    target_normals, target_distances - source_distances, rcond=None
)[0]
```

每个平面等权，避免仅由某块采样特别密的墙面主导结果。A/B分别求解检查一致性，再联合两组的6个平面对求一个候选。平面方向矩阵若秩不足就拒绝：只有一面墙无法约束沿墙滑动，只有两面竖墙也不能充分确定垂直平移。

这是带噪声下的分步估计；当法线本身有误差时，不保证所有平面都能被同一个刚体变换精确重合。现有地面差异正是需要继续检验的证据，不能把本方法等价成完整内参标定或已保证准确的最终解。

本次A/B独立解差7.11mm/0.211°；更换随机种子复核，联合解变化最大约0.641mm/0.00849°。这是重复性/敏感性指标，不是相对真实安装尺寸的误差上限。

## 6. 冻结、独立验证及误差含义

新方法形成前已经看过C，所以C不能再用作新方法的最终独立验收。先保存候选及配置哈希，再采未看过的新位置D。

`validate_frozen_candidate.py`校验候选、配置、设备和采集独立性，直接评价已冻结变换；不会在D上重新拟合双雷达外参。静止性检查仍会分别配准每台自己的时间前后半段。

`calibrate.py:evaluate()`双向评价前左→后右和后右→前左：对距离小于15cm且目标邻域为平面的有效对应，合并计算点到平面RMSE和绝对残差P95，同时报告两个方向中较少的匹配点数，以及10cm内较小覆盖比例。不能只报RMSE而忽略可见范围和匹配数量。

D结果：RMSE20.14mm、P9539.44mm、匹配点21008、覆盖48.39%，通过本次预设门限。该残差并非所有点的最大误差，也不是车体定位精度或雷达测距真值误差。

## 7. 地面专项与车体外参

`车体外参核对_20261125/audit_ground.py`只使用旧CAD缩小可能地面的搜索范围，再独立拟合每台雷达的地面；不强制法线水平、不强制平面高度、不更改相对候选。对于朝上的单位法线，雷达原点离地面垂距可由平面距离得到；法线与雷达本机Z轴夹角给出总倾斜角。

当前两台地面仍有约15.6–23.1mm高度差；同一个共同车体刚体变换不能消除雷达之间的相对不一致。前后/左右位置、车体原点和机械前向也不能单由这面地面恢复。

因此，最终使用链条仍为：确认机械车体基准 → 核对后右绝对安装锚点 → 乘以相对变换导出前左 → 核对地面/墙面与实测尺寸 → 新数据验证 → 静止融合 → 低速建图与动态时间检查。当前尚未进入正式外参部署或自主导航验收。
